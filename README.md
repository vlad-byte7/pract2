# Визуализация зависимостей Maven — вариант 19

Консольная программа читает настройки из CSV и строит граф прямых и
транзитивных зависимостей. Источник данных — Maven-репозиторий или локальный
тестовый CSV. Нужен Python 3.10 или новее. Устанавливать зависимости не нужно.

## Запуск и тесты

В терминале VS Code из папки проекта:

```powershell
.\run.bat .\config.csv
py -3 -m unittest discover -s tests -v
```

`run.bat` без аргументов использует `config.csv` из папки проекта и ждёт
нажатия клавиши после вывода. Это позволяет прочитать результат после
двойного щелчка по файлу. С явным путём к CSV паузы нет.

Если в системе используется команда `python`, тесты можно запустить через
`python -m unittest discover -s tests -v`.

## Настройки

Файл `config.csv` сохраняется в UTF-8, без заголовка. Каждая строка содержит
один параметр и его значение, разделённые запятой.

| Ключ | Пример | Назначение |
| --- | --- | --- |
| `package` | `org.apache.commons:commons-text:1.11.0` | Координаты Maven-пакета в формате `groupId:artifactId:version`. В тестовом режиме указывается одна буква от A до Z. |
| `repository` | `https://repo.maven.apache.org/maven2` | URL репозитория при `false`. Путь к существующему файлу при `true`. Относительный путь считается от папки с CSV. |
| `test_mode` | `false` | При `false` используется URL, при `true` — локальный файл. |

## Граф Maven

Для `org.apache.commons:commons-text:1.11.0` программа обращается к пути
`org/apache/commons/commons-text/1.11.0/commons-text-1.11.0.pom`.
Она читает раздел `<dependencies>`. Для подстановки версий учитываются
свойства POM, родительские POM и `dependencyManagement`, в том числе
импортируемые BOM. Третий этап строит граф для потребителя пакета из
обязательных зависимостей с областями `compile` и `runtime`.
При сравнении с Maven учитывайте ограничения реализации: профили,
`exclusions`, выбор версии при конфликте и диапазоны версий не обрабатываются.
Поиск сборок SNAPSHOT по метаданным также не реализован.

## Обход в ширину

BFS использует очередь. Сначала обрабатывается корневой пакет, затем его
прямые зависимости, затем пакеты, обнаруженные через них. Пакет попадает в
очередь один раз. Все найденные связи сохраняются, включая обратные связи
при цикле. В консоли каждая строка показывает пакет и его непосредственных
соседей в графе.

## Демонстрация на тестовом репозитории

В тестовом CSV нет заголовка. Первый столбец — пакет, остальные — его
прямые зависимости. Каждому пакету нужна своя строка. Если зависимостей нет,
строка содержит только букву пакета. Пример из `examples/repository.csv`:

```csv
A,B,C
B,D
C,D
D
```

Для демонстрации запустите из папки проекта:

```powershell
.\run.bat .\examples\branching.csv
.\run.bat .\examples\cycle.csv
.\run.bat .\examples\isolated.csv
```

| Конфигурация | Что проверить |
| --- | --- |
| `branching.csv` | Из `A` доступны `B` и `C`, обе связи к `D` видны. Порядок строк — `A, B, C, D`. |
| `cycle.csv` | Связи `E → F` и `F → E` выведены, программа завершилась. |
| `isolated.csv` | Для `G` выводится одна строка без зависимостей. |

## Порядок загрузки

Флаг `--load-order` выводит зависимости раньше пакетов, которым они нужны.
Программа использует топологическую сортировку. Сначала в очередь попадают
пакеты без зависимостей. После обработки каждого пакета программа уменьшает
число оставшихся зависимостей у его потребителей. Когда это число становится
нулём, потребитель тоже попадает в очередь. Корневой пакет в вывод не входит.

```powershell
.\run.bat .\examples\branching.csv --load-order
.\run.bat .\examples\cycle.csv --load-order
.\run.bat .\examples\isolated.csv --load-order
```

| Конфигурация | Результат |
| --- | --- |
| `branching.csv` | `D -> B -> C`. Общая зависимость `D` появляется один раз, перед `B` и `C`. |
| `cycle.csv` | Порядок построить невозможно. Программа сообщает о цикле и завершается с кодом 1. |
| `isolated.csv` | `Нет зависимостей.` |

Для проверки на том же графе в Maven 3.9.9 подготовлены четыре модуля
в `examples/maven`. Из папки проекта выполните:

```powershell
mvn -o -f .\examples\maven\pom.xml validate
```

В разделе `Reactor Build Order` Maven вывел `d, b, c, a, comparison`.
`a` — корневой модуль, а `comparison` — проект, объединяющий модули.
Порядок остальных трёх совпал с выводом Python: `D -> B -> C`.

Отдельно на этих же POM проверена фактическая загрузка JAR. Maven Resolver
1.9.22 из Maven 3.9.9 использовал файловый репозиторий, пустой кэш и один
поток загрузки. Он получил JAR в порядке `a, b, d, c`. Среди зависимостей
`b` загрузился раньше `d`: скачать JAR можно до скачивания JAR его
зависимостей. Наш порядок описывает готовность пакетов к использованию.
В Maven ему соответствует порядок сборки модулей. Порядок загрузки файлов
в отдельном запуске зависит от обхода графа, кэша и числа потоков.

## Демонстрация обработки ошибок

Перед каждым запуском поменяйте одну строку в исходном `config.csv`:

| Строка | Сообщение |
| --- | --- |
| `package,commons-text` | `Ошибка: package: нужен формат groupId:artifactId:version` |
| `repository,maven2` | `Ошибка: repository: нужен корректный URL с http:// или https://` |
| `test_mode,yes` | `Ошибка: test_mode: допустимы только true и false` |

## Функции

- `main` читает аргументы и выводит граф или ошибку.
- `load_graph` выбирает источник зависимостей и запускает BFS.
- `build_graph` обходит пакеты по очереди и возвращает список смежности.
- `dependency_load_order` сортирует граф и сообщает о цикле.
- `load_test_repository` читает и проверяет локальный CSV с графом.
- `load_config` читает и проверяет конфигурацию.
- `read_settings` разбирает строки CSV и проверяет список ключей.
- `validate_settings` проверяет значения в соответствии с выбранным режимом.
- `validate_url` проверяет адрес Maven-репозитория.
- `pom_url` строит адрес POM по координатам пакета.
- `fetch_pom` скачивает POM и разбирает XML.
- `read_model` собирает объявления проекта и учитывает родительские POM и BOM.
- `direct_dependencies` возвращает список координат прямых зависимостей.
- `runtime_dependencies` выбирает зависимости для графа Maven.
